### 一、 日志级别定义 (打什么级别)

严格区分“调试”与“运行记录”：

| 级别 | 英文 | 适用场景 | 包含在 Release 中？ |
| :--- | :--- | :--- | :--- |
| **调试** | `DEBUG` / `TRACE` | 变量值追踪、函数进入/退出、AI 原始 JSON 解析过程、目录扫描的每个文件遍历。**仅用于开发期找 Bug。** | **否** (被 Vite/Rust 剔除或过滤) |
| **信息** | `INFO` | 关键业务节点。如：应用启动、项目切换成功、AI 分析开始/结束、设置保存成功、用户导出文件。 | **是** |
| **警告** | `WARN` | 非致命异常。如：AI 返回格式不规范触发了容错解析、目录扫描跳过无权限文件夹、API Key 解密失败回退到明文。 | **是** |
| **错误** | `ERROR` | 致命异常/阻断性错误。如：网络断开导致 AI 请求失败、文件读写权限拒绝、数据库/JSON 损坏。 | **是** |

### 二、 输出目标 (输出到哪)

根据环境动态切换输出目的地：

| 运行环境 | 前端 (React) | 后端 (Rust) |
| :--- | :--- | :--- |
| **开发期 (`pnpm tauri dev`)** | 浏览器 DevTools 控制台 (Console) | 终端控制台 (Terminal) |
| **发布期 (`pnpm tauri build`)** | **不输出** (被 Vite 剔除)。若需记录严重错误，通过 IPC 传给后端。 | 本地日志文件 (日期轮转，如 `app_2026-07-28.log`，存放于 `%APPDATA%` 或用户数据目录) |

### 三、 日志格式 (格式是什么)

为了保证日志的可读性和可检索性，统一采用以下格式（Rust 的 `tracing-subscriber` 或 `env_logger` 可自动配置）：

`[时间戳] [级别] [模块/命令名] 消息内容`

**示例：**
*   `[2026-07-28 14:30:01] [INFO] [cmd::ai] 开始执行核心分析，项目ID: proj_123`
*   `[2026-07-28 14:30:05] [WARN] [svc::ai_parser] AI 返回 JSON 格式错误，已启用容错解析链`
*   `[2026-07-28 14:30:06] [ERROR] [cmd::data] 导出全部数据失败: 磁盘空间不足 (OS Error 112)`

### 四、 在哪打 (具体位置规范)

*   **前端 (`src/lib/logger.ts`)**：
    *   **禁止**在组件渲染逻辑中打日志。
    *   **只在**用户主动触发的关键操作（如点击“AI 分析”、点击“导出”）和捕获到的全局错误（ErrorBoundary）中，调用 `logger.info/error`，并通过 Tauri IPC 将其写入后端的本地日志文件。
*   **后端 (`src-tauri/src/commands/` 和 `services/`)**：
    *   **commands 层**：记录用户操作的入口和最终结果（INFO/ERROR）。
    *   **services 层**：记录核心业务逻辑的分支和异常（WARN/ERROR）。
    *   **禁止**在 models 层打日志。
