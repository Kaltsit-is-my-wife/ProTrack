# 应用数据管理原则

## 一、数据分类原则

### 1.1 按生命周期分类

| 类别 | 定义 | 示例 |
|------|------|------|
| **配置数据** | 应用行为偏好，用户明确设置 | API Key、主题、默认深度、窗口大小 |
| **业务数据** | 用户操作产生的核心内容 | 项目列表、状态、备注、AI 历史 |
| **模板数据** | 可自定义但带默认值的文本 | Prompt 模板、导出格式模板 |
| **缓存数据** | 可重建的临时内容 | 目录扫描缓存、AI 响应缓存 |
| **日志数据** | 调试和审计信息 | 操作日志、错误日志 |

**规则**：同类数据必须统一管理，禁止分散存储。

### 1.2 按归属分类

| 类别 | 定义 | 规则 |
|------|------|------|
| **应用级数据** | 与具体项目无关，全局生效 | 单例存储，应用启动时加载 |
| **项目级数据** | 绑定特定项目，随项目迁移 | 跟随项目目录或用户指定数据目录 |
| **会话级数据** | 仅当前窗口有效，关闭即丢 | 不持久化，存内存 |

## 二、存储位置原则

### 2.1 应用级数据

**规则**：使用系统标准应用数据目录。

- Windows: `%APPDATA%/<app-name>/`
- macOS: `~/Library/Application Support/<app-name>/`
- Linux: `~/.config/<app-name>/`

**示例**：
```
%APPDATA%/project-tracker/
  config.json       # 配置聚合文件
  window-state.json # 窗口状态
  logs/
    app.log
    app.old.log
```

### 2.2 项目级数据

**规则**：跟随用户指定的数据目录，或项目根目录。

**示例**：
```
用户指定目录/
  projects.json              # 项目列表与状态
  prompts.json               # Prompt 模板
  .project-tracker/           # 应用内部文件（用户不直接编辑）
    internal-state.json
    cache/
      scan-cache/
      ai-response-cache/
```

### 2.3 禁止行为

- **禁止**将业务数据写入 `%TEMP%`
- **禁止**将配置数据写入项目目录（除非用户明确导出）
- **禁止**在代码目录（`src/`、`node_modules/` 旁）存放任何运行时数据
- **禁止**使用浏览器 localStorage 存业务数据（Tauri 应用应该用后端存储）

## 三、数据格式原则

### 3.1 文件格式选择

| 数据类型 | 推荐格式 | 理由 |
|---------|---------|------|
| 结构化配置 | JSON | 人类可读，广泛支持 |
| 大型结构化数据 | JSON Lines / SQLite | 增量读写性能 |
| 用户可编辑文本 | Markdown / Plain Text | 外部编辑器友好 |
| 二进制数据 | 原生格式 | 无需转换 |

### 3.2 版本控制

**规则**：所有持久化数据文件必须包含版本字段。

```json
{
  "version": "1.0",
  "last_modified": "2026-07-19T22:38:00+08:00",
  "data": { ... }
}
```

**迁移规则**：
- 读取时检查版本，旧版本自动迁移
- 迁移失败时保留原文件，创建新版本文件
- 不向用户暴露版本号，静默处理

## 四、读写操作原则

### 4.1 原子写入

**规则**：写文件必须先写临时文件，再原子替换。

```
写入流程：
1. 写入 data.json.tmp
2. fsync 确保落盘
3. 重命名 data.json.tmp → data.json
4. 删除旧备份（如有）
```

**目的**：防止写入中断导致文件损坏。

### 4.2 读写分离

**规则**：
- 启动时：一次性加载所有必要数据到内存
- 运行时：只读内存，不写磁盘
- 变更时：更新内存 + 异步写磁盘（debounce 500ms）
- 退出时：强制同步写一次

**禁止**：每次用户操作都同步写磁盘。

### 4.3 错误处理

**规则**：
- 读失败：使用默认值，记录警告日志，不阻断启动
- 写失败：保留内存数据，提示用户"保存失败"，提供重试
- 格式损坏：备份损坏文件，创建新文件，提示用户

---

## 五、用户可见性原则

### 5.1 透明存储

**规则**：用户应该知道数据存在哪里。

- 设置页面显示数据目录路径
- 提供"打开数据目录"按钮
- 数据迁移时提示原位置和新位置

### 5.2 可导出

**规则**：所有业务数据必须支持导出。

- 项目数据 → JSON 导出
- 配置 → JSON 导出
- 提供"导出全部数据"功能

### 5.3 可清理

**规则**：缓存和日志必须可清理。

- 设置页面提供"清理缓存"按钮
- 日志自动轮转，保留最近 N 天
- 卸载应用时询问是否删除数据

---

## 六、具体执行 checklist

agent 整理数据时，逐条确认：

- [ ] 列出当前所有散落的数据存储位置
- [ ] 按上述分类归入配置/业务/模板/缓存/日志
- [ ] 确定每个类别的最终存储位置
- [ ] 实现数据迁移逻辑（旧位置 → 新位置）
- [ ] 添加版本字段到所有数据文件
- [ ] 实现原子写入
- [ ] 实现内存缓存 + 异步落盘
- [ ] 设置页面显示数据目录并提供打开按钮
- [ ] 测试：关闭应用 → 修改数据文件 → 重新打开 → 数据正确加载
